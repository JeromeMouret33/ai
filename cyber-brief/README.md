# Brief cyber hebdomadaire — v2

Couple **prompt + template** pour la newsletter cyber du consultant
(audit ISO 27002, EBIOS RM, NIS2/DORA/CRA, gestion de crise ; clients santé,
OIV/OSE, collectivités ; zone prioritaire océan Indien).

## Fichiers
- **`PROMPT.md`** — prompt v2, cadré section par section (à coller dans l'outil
  de génération chaque semaine).
- **`template.html`** — template HTML restructuré, rempli avec l'édition du
  6 juillet 2026 comme démonstration du nouveau format.

## Ce qui change par rapport à la v1 (retours de revue du 06/07/2026)

| Bloc | v1 | v2 |
|---|---|---|
| Tête | SITREP : jauge de menace + KPI bruts (nb vulns, nb victimes…) — **bruit** | **Édito « Le fil de la semaine »** : 2-4 phrases qui *relient* les 5 sujets (le liant analytique), sans les répéter |
| Sujet 01 | « Vulnérabilité · exploitation active » (large) | **« À patcher cette semaine »** : strictement CISA KEV, actif courant exposé Internet, non nicher |
| Sujet 02 | Ransomware (liste de victimes) | Ransomware : **exemple de fuite** (traqueurs bonjourlafuite/ransomware.live) + **topo mode opératoire** du groupe le plus actif |
| Sujet 03 | Menace émergente / IA | Inchangé (framing « analyse / signal fort ») |
| Sujet 04 | Réglementaire | Inchangé |
| Sujet 05 | Océan Indien | Inchangé |
| Focus | Pavé de texte | **Avis d'experts** courts (sécurité industrielle / gestion de crise / audit / sensibilisation) |
| — | (absent) | **Annexe « À patcher »** : tableau des CVE exploitées sur actifs courants |

## Règle directrice
Rien qui ne soit **actionnable en réunion client**. Pour les
vulnérabilités : uniquement **publié + connu + activement exploité** sur un
**actif courant exposé sur Internet** — « qu'est-ce qu'il faut patcher cette
semaine pour ne pas se faire hacker ». Le reste part en annexe.
